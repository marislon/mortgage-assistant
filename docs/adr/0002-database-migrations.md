# ADR-0002: Управление миграциями базы данных

**Статус:** Принято

## Контекст

Система ипотечного кредитования использует PostgreSQL для хранения данных о кредитах.

По мере развития приложения структура таблиц будет изменяться. Необходимо обеспечить воспроизводимость изменений и согласованность схемы базы данных с моделями SQLAlchemy.

## Решение

Для управления изменениями структуры PostgreSQL используется **Alembic** совместно с SQLAlchemy.

Приняты следующие правила:

- Структура таблиц описывается моделями SQLAlchemy.
- Изменения схемы оформляются отдельными миграциями Alembic.
- Перед применением автоматически созданная миграция проверяется разработчиком.
- Миграции сохраняются в Git вместе с исходным кодом.
- Адрес базы данных Alembic получает из настроек приложения через `.env`.
- Миграции применяются командой `uv run alembic upgrade head`.

Первая миграция `bcd4b30f20ca` создаёт таблицу `loans`.

## Альтернативы

1. Создавать и изменять таблицы вручную через SQL.
2. Использовать `Base.metadata.create_all()` при запуске приложения.
3. Использовать другой инструмент миграций.

## Почему выбран Alembic

Alembic позволяет хранить историю изменений схемы, применять их последовательно и при необходимости создавать обратные операции.

Он хорошо интегрируется с SQLAlchemy, который уже используется в проекте.

## Компромиссы

Автоматическая генерация миграций требует проверки. Некоторые изменения структуры данных нельзя безопасно выполнить без дополнительного SQL-кода.

Откат миграции также не всегда означает возможность восстановления удалённых данных.

## Когда пересматривать

Решение следует пересмотреть, если изменится используемая СУБД или появятся требования к более сложному управлению миграциями в нескольких окружениях.
