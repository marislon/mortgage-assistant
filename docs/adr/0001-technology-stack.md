# ADR-0001: Выбор технологического стека

**Статус:** Принято

## Контекст

Разрабатывается система ипотечного кредитования с API, финансовыми расчётами, хранением кредитов и возможностью дальнейшей интеграции LLM.

Система должна обеспечивать точность денежных вычислений, надёжное хранение данных и возможность дальнейшего расширения.

## Решение

Для реализации проекта выбран следующий стек:

- **Python 3.12** — основной язык разработки.
- **FastAPI** — создание HTTP API.
- **uv** — управление зависимостями и виртуальным окружением.
- **PostgreSQL 16 с pgvector** — хранение данных и возможность векторного поиска в будущем.
- **SQLAlchemy** — работа с базой данных через ORM.
- **Alembic** — управление изменениями структуры базы данных.
- **Docker Compose** — запуск инфраструктурных сервисов.
- **Temporal** — оркестрация длительных процессов (планируется подключение).
- **pytest** — автоматическое тестирование.

Финансовые расчёты выполняются в Python с использованием целых копеек и `Decimal`. LLM не используется для вычисления денежных сумм.

## Альтернативы

- Django вместо FastAPI.
- SQLite вместо PostgreSQL.
- Ручное управление SQL-схемой вместо Alembic.

## Почему выбран этот подход

FastAPI подходит для асинхронного API, PostgreSQL обеспечивает надёжное хранение структурированных данных, а Alembic позволяет контролировать изменения схемы.

Выделение финансовой логики в отдельные Python-функции делает расчёты воспроизводимыми и тестируемыми.

## Компромиссы

Выбранный стек требует настройки нескольких компонентов и сложнее простого приложения с SQLite.

Temporal добавит инфраструктурную сложность, но позволит управлять длительными процессами.

## Когда пересматривать

Решение следует пересмотреть, если изменятся требования к нагрузке, инфраструктуре, хранению данных или длительным бизнес-процессам.
